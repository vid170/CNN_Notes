ConvNeXt — One-Page Notes

"A ConvNet for the 2020s" — Liu et al., 2022 (Facebook AI Research). A pure ConvNet, modernized by systematically borrowing design choices from Vision Transformers (especially Swin), starting from a ResNet-50 and applying changes one at a time. No attention, no patches-as-tokens — just convolutions, redesigned.

Macro Design: Stage Ratio & Stem

Stage ratio 3:4:6:3 → 3:3:9:3

  • Both networks have 16 blocks total, just redistributed across the 4 stages — more blocks shifted into stage 3 (Swin-style 1:1:3:1 ratio), fewer in stage 2.

"Patchify" stem (4×4, stride 4)

OperationsOutput before Stage 1
ResNet-507×7 conv (stride 2) → 3×3 max-pool (stride 2)56×56×64
ConvNeXt-Tsingle 4×4 conv (stride 4)56×56×96
  • Input is 224×224×3 for both; both reach the same 56×56 spatial size before Stage 1.
  • ResNet downsamples gradually in two overlapping-receptive-field ops; ConvNeXt does it in one non-overlapping strided conv — same idea as ViT's patch embedding (each 4×4×3 patch → one 96-d token).

Block Architecture: ResNet vs ConvNeXt

ResNeXt-ify: Grouped/Depthwise Conv + Width Increase

  • Grouped conv (from ResNeXt): splits channels into g groups, each convolved independently — cheaper than a standard conv by a factor of g.
  • ConvNeXt takes this to the extreme: depthwise conv is a grouped conv with g = number of channels (each channel gets its own filter) — massive FLOP/param savings.
  • Those savings are reinvested into width: base channels bumped from ResNet's 64 → 96 at stage 1, keeping total network compute matched to the ResNet-50 baseline instead of shrinking the model.
  • Net effect: ~79.5% → ~80.5% Top-1, roughly same compute budget.

Key Architectural Ideas

Inverted bottleneck (borrowed from MobileNetV2)

  • ResNet bottleneck: wide → narrow → wide (256→64→64→256), standard 3×3 conv in the middle
  • ConvNeXt block: narrow → wide → narrow (96→384→96), depthwise 7×7 conv at input width
  • Mimics a Transformer block: spatial mixing (like attention) → wide MLP-style channel mixing

Depthwise separable convolution — the real compute-saving trick

  • Standard conv FLOPs: H×W × C_in × C_out × K²
  • Depthwise conv FLOPs: H×W × C × K² (no cross-channel term)
    • Makes a large 7×7 kernel ~96× cheaper than a standard 7×7 at the same channel count — this is what lets ConvNeXt afford a big receptive field (ViT-style) without exploding compute.

Fewer & Different Activation Functions

  • Reduced activation functions: ConvNeXt reduces the number of activations used throughout the network, streamlining the architecture — just 1 per block instead of 3.
  • GELU over ReLU: ConvNeXt adopts GELU (Gaussian Error Linear Unit) instead of ReLU.
  • GELU formula: GELU(x) = x·Φ(x) = x · ½[1 + erf(x/√2)], where erf(x) is the Gaussian error function.

Micro Design (Transformer-Style Layer Choices)

  • 1 normalization layer per block (not 3) — placed before the first 1×1 conv
  • 1 activation per block (GELU, not ReLU) — placed between the two 1×1 convs
  • BatchNorm → LayerNorm

Common Misconception (Worth Remembering)

ConvNeXt blocks are not individually cheaper than ResNet blocks at matched channel width — an inverted-bottleneck block with 4× expansion actually costs more FLOPs per block than a ResNet bottleneck at the same width. The efficiency gain comes from:
  • Depthwise convs making large kernels cheap (real saving)
  • Network-level tuning — ConvNeXt uses narrower base channel widths per stage than ResNet, so total-network FLOPs land close to ResNet's (ConvNeXt-T: 4.5 GFLOPs vs ResNet-50: 4.1 GFLOPs — matched, not lower)
So the real story: better accuracy per FLOP, not fewer FLOPs overall.

What the Paper Does Not Claim

  • No memory or latency numbers are reported for individual micro-design changes (e.g., "fewer norm layers") — only accuracy deltas in the ablation table.
  • Final throughput comparisons (ConvNeXt vs Swin vs ResNet on A100 GPUs) are reported only for the complete final models, as an aggregate effect of all changes combined.
